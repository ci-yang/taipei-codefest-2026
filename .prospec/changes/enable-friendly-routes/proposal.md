# 友善同行：開啟就找得到、斷網也帶得走的友善資源地圖

> 第三版規格（依 D6 改寫）｜主流程：開啟即定位並顯示地圖 → 搜尋目的地 → 底部類別鈕 highlight 該類店家 → 點店家看卡片 → 導航或撥號。離線可用為主功能。多站行程與日期歷史為次要（P1），非 demo 主流程。

## Background
Ci 提供的需求，將友善店家名冊延伸為「外出途中取得資源」的入口；主要服務缺乏穩定網路或電力的市民，對應競賽「拿不到」。官方開放名冊有店家位置及服務標籤，但沒有即時可用狀態與免消費條件；現有官網已能依友善項目篩選並提供單店路線入口。D6 拍板：主流程單一，離線為主功能，且本作品不做任何使用者之間或使用者對店家的互動功能（互助、品質回報、協助者模式、評論、檢舉、求助皆不做）。能否改善目標族群取得資源的結果，仍是待實測的產品假設。

## User Stories

> 編號說明：US-3、US-5 已移除（見 Background，D6），US-6 併入 US-1；其餘編號沿用不重排。

### US-1: 開啟即定位，按類別找到附近店家 [P0]
作為外出的市民，我想一開啟就看到自己在地圖上的位置，按一下類別鈕就看到該類店家，以便立刻前往或聯絡。
**Acceptance Scenarios:**
- WHEN 我開啟首頁並允許定位，THEN 定位、導航、撥號依 `docs/townpass-integration.md` 的協定，在原型內以純 JS 實作等價的 bridge 呼叫（`flutterObject.postMessage` 加 message 事件回覆；可移植 `apps/web/src/composables/useTownPassBridge.ts` 的邏輯，但不 import Vue、不依賴 apps/web），地圖標示回傳的目前位置、定位精度與取得時間，不將示範座標標成 GPS。
- WHEN bridge 定位回傳空陣列 `[]` 或失敗，THEN 顯示統一狀態「無法取得定位」與重新定位入口；只有退到瀏覽器 `navigator.geolocation` 的降級路徑時，才細分拒絕、逾時、不支援。
- WHEN 定位精度 accuracy 大於 100 m，THEN 視為精度不足並標示；精度不足仍顯示該位置並標「精度不足」，算有效位置（100 m 為暫定門檻，計畫站可調）。
- WHEN 沒有有效位置，THEN 地圖改以預設市中心呈現並提示「目前非您的位置」；不顯示定位成功，距離與方位改以地圖中心估算並明示。
- WHEN 我在搜尋框輸入目的地，THEN 先比對本機已快取點位的名稱與地址，再視網路狀態使用線上地理編碼（Photon，開源、OSM 資料）；地圖移至該處並可從該處查看各類店家；查無結果時說明原因，不捏造地點。離線時隱藏線上來源並明示「僅搜尋已下載資料」。呼叫 Photon 不帶使用者座標；畫面常駐標示 © OpenStreetMap contributors（ODbL），Photon 列入 SC-007 的來源清單。
- WHEN 我按底部類別鈕（離線時亦可用；廁所、充電、Wi-Fi、無障礙，類別可擴充；Wi-Fi＝名冊 Wi-Fi 標記店家加公眾區免費無線上網熱點的聯集；熱點卡片顯示熱點名稱、地址、來源，無電話不顯示撥號），THEN 地圖 highlight 該類店家：初始顯示全部點位（一般樣式），選類別後符合者放大、加亮、加類別圖示，不符合者降低不透明度但不移除；再按一次取消；可同時選多類，明示多選為「任一符合」；「範圍」指目前地圖視窗，該範圍無符合者時顯示零筆。
- WHEN 我點選店家，THEN 顯示卡片：名稱、距離（一律為直線距離，畫面統一標「直線距離（非步行路線）」，線上離線同一規則）、類別、資料來源與更新日；空白標記顯示「未標示」，未確認條件顯示「待確認」，不宣稱免費免消費或目前可用。
- WHEN 卡片資料含電話，THEN 顯示「撥號」並透過 TownPass bridge `phone_call` 撥出；無電話欄位則不顯示該按鈕。
- WHEN 我按卡片上的「導航」，THEN 透過 TownPass bridge `launch_map` 傳入 `geo:<lat>,<lon>?q=<lat>,<lon>(<店名 URL encode>)` URI，交給裝置預設地圖 App；不得寫死 Google 或 Apple Maps 網址。geo URI 回 false 或逾時（5 秒）時，以 `launch_map` 再送一次 OSM 網址 `https://www.openstreetmap.org/?mlat=<lat>&mlon=<lon>#map=18/<lat>/<lon>`。
- WHEN OSM 網址也回 false 或逾時（5 秒，規格設定值；bridge 文件為一定回覆，逾時只是防呆），THEN 顯示「無法開啟外部地圖」並保留地址可複製，不顯示已開啟。`phone_call` 回 false 或逾時即顯示「無法撥號」並保留電話可複製。
- WHEN flutterObject 不存在（一般瀏覽器），THEN 導航與撥號按鈕仍顯示，按下後說明「需在台北通 App 內使用」，保留地址與電話可複製，不呼叫 postMessage。
**Independent Test:** 分別注入已知位置、bridge 回空陣列（一案例）、瀏覽器降級路徑的拒絕、逾時、不支援（各一案例）與 accuracy 大於 100 m（一案例），核對顯示值與預設市中心提示；逐一切換四類鈕與取消，逐筆對照固定資料集的服務標記；點卡片核對來源與更新日，並驗證 `launch_map` 的 geo URI 與 `phone_call` 的呼叫參數（有電話才出現撥號），並模擬 geo URI 回 false 或逾時後改送 OSM、OSM 也失敗，以及 `phone_call` 回 false 與逾時。一般瀏覽器（無 flutterObject）按導航與撥號各一案例，須顯示「需在台北通 App 內使用」且不拋錯。搜尋分別在線上與離線各測一次。於 390px 寬度操作無水平溢出。

### US-2: 比較多站行程的建議路線 [P1]
非 demo 主流程，主流程穩定後才做。
作為安排外出的市民，我想比較較短與資源較多的路線，再選擇適合這次行程的方案。
**Acceptance Scenarios:**
- WHEN 我設定有效起點與依序經過的 1–5 個目的地並按下一步，THEN 進入獨立確認頁，顯示可用路線、各站順序、距離、符合需求的沿線店家數與類別。
- WHEN 系統提出「最短路徑」及「資源最多」方案，THEN 最短明示限定本次可用路網；資源最多明示限定本次產生的候選，按相同需求與距離範圍計算不重複店家數，並呈現兩者的距離與資源差異。
- WHEN 地點需要接至可用路網，THEN 只允許每段不超過 120 m（規格設定值，見 input-evidence.md 本輪修訂來源，非實測）的端點接線，另列接線距離並納入總距離，標示接線未驗證現場通行；超限即拒絕該地點並提供修改入口。
- WHEN 地點無法辨識、超出路網、路段不連通或沒有不同的替代方案，THEN 說明原因與可修改項目，不以直線跨越不連通路段、不捏造第二條路線；原型路線不保證現場通行或無障礙。
**Independent Test:** 固定起點及三目的地，逐一測試站序、增刪、方案切換與開始；以相同候選資料核對距離／去重店數，並測試單一路線、不連通、端點接線限內與超限情況。

### US-4: 離線也能用：快取全市點位，無底圖時給方向與距離 [P0]
作為可能途中斷網的市民（評審也可能現場關網路），我想斷網後仍能定位、找類別店家並知道往哪走。
**Acceptance Scenarios:**
- WHEN 首次有網路開啟，THEN 自動快取全市店家點位與類別（不只某條路線範圍）；底圖快取以目前視窗附近為限，並明示底圖涵蓋範圍；快取進行中顯示進度。
- WHEN 全市點位、類別資料與頁面本身都快取成功，THEN 才顯示「已快取」及儲存時間與底圖涵蓋範圍；任何一項快取失敗都不得顯示「已快取」，並說明缺哪一項。
- WHEN 斷網並重開頁面，THEN 仍可定位、按類別鈕 highlight、點店家看卡片，並以直線計算距離與方位；底圖範圍外只顯示店家點位，不假裝有底圖。
- WHEN 斷網且目前位置沒有底圖，THEN 提供「方向與距離」導引畫面：文字寫成「店家在您的東北方（以正北為基準），約 120 公尺」（數字僅為示意），不需羅盤也能顯示；有方位感測時才轉動大箭頭指向所選店家，不需要路網；無方位感測時，畫面上方視為正北，靜態箭頭指向店家方位角，並標「以正北為基準」。沒有有效定位時不顯示箭頭，只顯示「需要定位才能指向」與重新定位入口；方位感測不可用或被拒時，保留方位文字與距離並說明。
- WHEN 斷網時按「導航」或「撥號」，THEN 說明依賴外部程式或通話功能、可能無法使用，保留方向與距離導引及電話號碼供手動撥打；距離須標示「直線距離（非步行路線）」。
- WHEN 沒有已快取內容或要求快取範圍外的資料，THEN 說明缺少離線資料，保留仍可讀的內容。
**Independent Test:** 有網開啟並等待快取完成後，關閉網路重開頁面；在飛航模式下按各類別鈕仍有結果、點店家可看卡片與距離；於無底圖區域確認出現方向與距離導引，轉動裝置箭頭隨之改變；模擬任一項快取失敗，確認不顯示「已快取」；清除快取後重測無離線資料狀態。

### US-7: 選日期與重用歷史路線 [P1]
非 demo 主流程，屬第二層功能。
作為經常外出的市民，我想選擇出發日期並套用自己保存的行程，減少重複輸入。
**Acceptance Scenarios:**
- WHEN 我進入行程設定頁，THEN 可選日期、歷史路線、起點及目的地；新行程預設裝置當日日期與可用的目前位置，畫面不依選定日期宣稱店家正在營業。
- WHEN 我確認路線並明確選擇保存為歷史，THEN 才將日期、起迄點及選定方案存入本機歷史；初始歷史為空，保存失敗不得顯示成功。
- WHEN 我套用或刪除歷史行程，THEN 套用會還原站序與方案偏好、保留這次已選日期並重新計算，舊起點標為歷史起點；刪除後該筆不再出現。
**Independent Test:** 從空白儲存區確認路線；未保存時重開仍無歷史，保存後可套用與刪除；日期與起點來源須符合上述規則。

6. 導航與撥號依賴 TownPass bridge 的 `launch_map` 與 `phone_call`，在瀏覽器預覽下不可用，須以實機驗證；有電話欄位才顯示撥號。

10. TownPass WebView 斷網重開是否能由 Service Worker 載入頁面，待實機驗證；不可行時退路為「斷網時不重開頁面、以頁內狀態維持離線資料，並在 README 標明限制」。若啟用此退路，US-4、Independent Test、SC-004 的「斷網並重開頁面」一律改為「斷網後不重開，頁面仍可完成同樣操作」，並在 `docs/DECISIONS.md` 記錄；未啟用前以重開頁面為準。
11. 地圖採免費開源圖資（Leaflet（v4 現行）或 MapLibre，搭配 OSM 或 NLSC 圖資），禁商用地圖；非核心資料若為模擬，須標「模擬資料」。

## Edge Cases

- 座標缺漏或超出資料涵蓋範圍（離線時同樣適用）：名冊可查，但不能任意補點；提示無法顯示在地圖。
- 定位回傳太舊、低精度（P1／US-2：或定位期間起點已被手動修改）：提示重新定位，不用較晚回呼覆蓋手動起點；同名地點以地址辨識。
- 離線快取部分成功：已成功的部分仍可用，畫面明示缺哪一項，不顯示「已快取」。
- 快取版本與線上資料不一致：離線時顯示快取儲存時間，不把舊資料改標即時。
- 電話欄位為空或格式異常（離線快取亦同）：不顯示撥號，保留其他資訊。
- 離線或線上，類別鈕按下後視窗內無該類店家：顯示零筆，並提示可縮放或搜尋他處，不自動切換類別。

## Functional Requirements

- FR-001：開啟即定位、精度與時間顯示、失敗時預設市中心加提示、搜尋目的地（先比對已快取點位，線上用 Photon，離線隱藏線上來源；US-1）。定位、導航、撥號依 bridge 協定在原型內以純 JS 實作，accuracy 大於 100 m 視為精度不足（暫定）。
- FR-002：底部類別鈕（廁所、充電、Wi-Fi、無障礙，可擴充）、highlight 定義（全部一般樣式、符合者加亮放大、其餘降不透明度）、取消、多選任一符合、零筆處理（US-1）。
- FR-003：店家卡片（名稱、距離、類別、來源與更新日）、`launch_map` 導航（geo URI，失敗退 OSM 網頁）、失敗與逾時處理、無 bridge 時的降級說明、有電話欄位才顯示的 `phone_call` 撥號（US-1）。
- FR-004：離線快取：全市點位與類別、頁面本身（app shell）首次自動快取、底圖限目前視窗附近並明示範圍、全部成功才標「已快取」（US-4）。
- FR-005：斷網重開後的定位、highlight、卡片與直線距離方位；無底圖時的方向與距離導引（US-4）。
- FR-006：公廁、捷運無障礙與公眾區免費無線上網熱點等開放資料併入（含離線快取範圍）、每筆帶來源與更新日（US-1、US-4）。
- FR-007：多目的地固定站序、路線確認頁、最短與資源最多的差異（US-2，P1）。
- FR-008：日期選擇與本機歷史的明確保存、套用、刪除（US-7，P1）。

## Success Criteria

- SC-001：線上與離線下，固定資料集四類篩選結果與來源與更新日欄位逐筆一致；零筆與未知值各有一項通過案例。
- SC-002：定位成功一案例；失敗案例為 bridge 回空陣列一案例，以及瀏覽器降級路徑的拒絕、逾時、不支援各一案例，失敗時顯示預設市中心與提示；accuracy 大於 100 m 一案例，顯示該位置並標「精度不足」，不跳市中心。示範座標未被標成真 GPS。
- SC-003：實機上卡片的「導航」以 geo URI 呼叫 `launch_map`、「撥號」呼叫 `phone_call`；無電話的店家不出現撥號。geo URI 回 false 或逾時時改送 OSM 網址；OSM 也回 false 或逾時，才顯示「無法開啟外部地圖」。`phone_call` 回 false 或逾時顯示「無法撥號」。兩者失敗時都可複製地址與電話，不顯示已開啟。一般瀏覽器（無 flutterObject）按導航與撥號各一案例，顯示「需在台北通 App 內使用」、可複製地址與電話、不呼叫 postMessage、不拋錯。
- SC-004：關閉網路重開頁面後仍可定位、按類別鈕、看卡片與直線距離；飛航模式下按類別鈕仍有結果。
- SC-005：無底圖區域出現方向與距離導引，裝置轉向時箭頭隨之改變；方位感測不可用時有文字退路。
- SC-006：任一快取項目（含頁面本身）失敗時不顯示「已快取」；全部成功才顯示儲存時間與底圖涵蓋範圍。
- SC-007：畫面（含離線狀態）和交付文件列出每個資料集來源與更新日；模擬資料皆有標記；不得把測試成功率寫成使用者成效。
- SC-008（P1）：多站比較距離與去重店數可由固定資料重算；空白歷史、保存成功與失敗、套用與刪除均有案例。
- SC-009：390px 寬度主流程可走完且無水平溢出。
- SC-010：搜尋線上可找到已快取點位與地理編碼結果；離線只搜尋已下載資料並明示，不呼叫線上來源。

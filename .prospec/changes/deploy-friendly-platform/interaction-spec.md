# Interaction Spec：平台整合頁
> 來源：proposal.md + design-spec.md；DSL Version: draft-1；2026-11-07。

## Screens
### 友善地圖
| 狀態 | 說明 | 進入條件 |
|---|---|---|
| Empty | 尚無名冊 | 首次進入 |
| Loading | 請求名冊／圖資 | 進入或重試 |
| Loaded | 地圖與清單可操作 | 資料成功 |
| Partial | 清單可用、地圖或路網不可用 | 資產／WebGL 失敗 |
| Error | 無名冊可用 | API 失敗／逾時 |
| NoMatch | 篩選後零筆 | 合法篩選 |

```text
Empty -> Loading : 進入
Loading -> Loaded : 資料成功
Loading -> Error : 請求失敗／15秒逾時
Loaded -> Partial : 地圖或路網失敗
Error/Partial -> Loading : 點重試
Loaded -> NoMatch -> Loaded : 改服務條件
```

## Flows
### US-1／US-2：開啟真實資料
1. 開啟首頁或地圖深層路由 → 顯示載入狀態。
2. 名冊成功 → 顯示店家、服務與來源連結；失敗 → 明示錯誤與重試。
3. 點四類服務 → 清單與地圖採任一符合；零筆顯示空狀態。
4. 開來源頁 → 可讀日期、範圍、版本與開放資料連結。
### US-3：定位與路線
1. 請求當下位置 → 顯示定位中；12 秒無回覆 → 逾時及重試。
2. 收到位置 → 驗時間／精度／範圍；不合條件 → 原因與手選，不用展示中心代替。
3. 手選起點 → 舊定位請求失效，晚到不更動目前選擇。
4. 選目的地與服務 → 比較路線；路網失敗或無可達路線 → 留清單與明確訊息。
5. 點候選 → 地圖切換路線、顯示距離與資源；虛線接線另標未驗證。
6. 離開頁面 → 取消請求並移除地圖資源，避免晚到更新。
### US-4：App 入口
1. 開啟已建置 App 的友善服務 → 使用建置時 HTTPS URL。
2. 開啟位置權限 → 依實際 bridge 回應呈現；拒絕或低精度可手動操作。
3. 無實機時保留此流程為待驗項，不推論建置成功等於完成實測。
### US-5：部署交接
維運流程由命令與交接文件處理，不把 deploy／rollback 控制放進公開產品畫面。

## Gestures
地圖可拖移與縮放；卡片／chip 點擊操作，鍵盤 Enter／Space 亦可。沒有隱藏的長按或滑動才能完成的必要動作。

## Micro-interactions
沿用現有按鈕狀態；不增加裝飾動畫。載入與錯誤用可讀文字，狀態改變使用適當 live region，保留鍵盤焦點。

## Responsive Interactions
手機與桌面相同選點流程；手機控制項單欄、觸控目標至少 40px；桌面可鍵盤操作。地圖失敗仍能靠清單選點，不阻擋核心資料閱讀。

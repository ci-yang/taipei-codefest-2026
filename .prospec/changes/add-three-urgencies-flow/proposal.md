# 三急首頁與開口卡：急的時候不看地圖

> 主流程：開啟 → 三顆大按鈕（廁所、充電、網路）→ 按下直接出「最近一家」結果卡 → 帶我去／開口卡／看地圖。現有地圖、目的地搜尋、多選、清單全部保留，降為第二層「看地圖」。本 change 建立在 `enable-friendly-routes`（定位、bridge、離線快取、資料併入、類別 highlight 的規格）之上，該 change 的 FR 與 SC 仍有效、不在此重述；本文只寫新增與改變的部分。

## Background
副局長看過 v6（main `c0486bb`）後的評語是「很基本、沒必要做成 app、要有亮點」。v6 的主流程是先看地圖、再選類別、再點店家，三步才到一家；急著找廁所的人不想看地圖。Ci 以分鏡「人有三急」（claude.ai artifact `PRJUafqt1tcodcbgtk4yCh`）定調新主流程：一鍵找到最近一家，走到門口再用開口卡把話說出來。D6 仍然有效：不做任何經平台的使用者互動；開口卡是面對面、零上傳、零配對的畫面，與撥號鍵同一層級。

## User Stories

### US-1: 三顆大按鈕，一鍵得到最近一家 [P0]
作為推著輪椅、雙手沒空的看護，或急著找廁所的長者，我想按一下就知道最近哪一家、往哪走，不用看地圖。
**Acceptance Scenarios:**
- WHEN 我開啟 App，THEN 首頁只有三顆全寬大按鈕「廁所」「充電」「網路」與一行定位狀態（沿用 `enable-friendly-routes` 的定位規則與「無法取得定位」狀態），沒有地圖、沒有歡迎頁、沒有交通偏好；另有「看地圖」與「設定」的小入口。
- WHEN 我按任一按鈕且有有效定位，THEN 3 秒內顯示結果卡：該類別中直線距離最近的一筆（名稱、直線距離、方向文字、無障礙標記「有／未標示」、來源與更新日），三顆動作鈕「帶我去」「開口卡」「看地圖」，以及「換下一家」（最多再看 2 筆次近）；若該筆為公眾 Wi-Fi 熱點（來源為免費熱點資料集，現場無店員），不顯示「開口卡」，只剩兩顆動作鈕。
- WHEN 我按按鈕但沒有有效定位，THEN 不出結果卡，顯示「需要定位才能找最近」、重新定位入口與「看地圖」；不以地圖中心假裝最近。
- WHEN 設定裡的「輪椅／推車」偏好開啟，THEN 只在該類別中有無障礙標記者挑最近；該類別一筆都沒有無障礙標記時，顯示最近一筆並標「無障礙資料不足」，不隱瞞也不假裝符合。
- WHEN 我按「網路」，THEN 類別為 Wi-Fi 聯集（名冊標記店家加公眾免費熱點，沿用既有定義），卡片標「免費 Wi-Fi 熱點，不保證訊號」，無電話不顯示撥號。
- WHEN 我按「帶我去」，THEN 進入導引畫面：沿用方向與距離導引（箭頭加「東北方約 120 公尺」）；若本機步行路網已就緒，另畫步行路線並顯示步行距離與估計分鐘，直線與步行兩個數字分別標「直線」「步行」；路網未就緒時只有箭頭，不等待下載、不顯示空白。
- WHEN 我按「看地圖」，THEN 進入現有地圖頁，該類別已 highlight、該筆置中並開卡，返回鍵回結果卡。
**Independent Test:** 注入固定位置與固定資料集，逐一按三顆按鈕，核對結果卡那一筆是否為該類別直線最近者，「換下一家」依序為第二、第三近；輪椅偏好開關各一案例（有無障礙標記者存在、不存在各一）；無定位一案例；路網就緒與未就緒各一案例，核對導引畫面的數字與標籤；390px 寬度無水平溢出。

### US-2: 開口卡，把最後兩公尺的話說出來 [P0]
作為中文不流利的看護，或不好意思開口借廁所的長者，我想把手機轉給店員就能表達需求。
**Acceptance Scenarios:**
- WHEN 我在結果卡或店家卡片按「開口卡」，THEN 全螢幕顯示雙面卡：上半為給店員看的中文大字（依類別固定一句，例如「您好，我想借用廁所，請問方便嗎？謝謝」），下半為我的母語同一句；兩面都附「不方便也沒關係，謝謝」。
- WHEN 我在設定選母語（中文、英文、印尼文、越南文），THEN 下半改為該語言；母語為中文時只顯示單面大字。
- WHEN 離線，THEN 開口卡仍可用，文案內建於 App，不呼叫任何線上翻譯或 LLM。
- WHEN 某語言的句子尚未經母語者校對，THEN 該語言不出現在語言清單；校對人與日期記錄於 README 資料來源表旁。
- WHEN 我關閉開口卡，THEN 回到原本的結果卡或店家卡片；開口卡不記錄、不送出、不提供店員回覆機制。
**Independent Test:** 三類別各開一次開口卡，核對中文句與所選母語句一一對應；切換四種母語各一案例；飛航模式開啟仍可顯示；檢查網路請求為零；檢查語言清單只含已校對語言。

### US-3: 地圖降為第二層，功能不刪 [P1]
作為想看附近還有哪些選擇的市民，我想在需要時打開完整地圖，但它不應擋在急用流程前面。
**Acceptance Scenarios:**
- WHEN 我從首頁或結果卡進入「看地圖」，THEN 現有地圖、目的地搜尋、多選類別、清單、快取狀態列全部保留並可操作；返回鍵回到來源畫面。
- WHEN 我在地圖點店家開卡，THEN 卡片除原有「導航」「撥號」外也有「開口卡」；該筆為公眾 Wi-Fi 熱點時不顯示「開口卡」。
- WHEN App 啟動，THEN route-experience 分支的歡迎頁「出發」鈕與步行、捷運、單車、開車偏好不出現在任何畫面。
**Independent Test:** 從首頁與結果卡各進入一次地圖並返回；在地圖開卡確認有開口卡；全文搜尋畫面無「出發」與交通偏好元件。

## Stated Assumptions

1. 名稱 `add-three-urgencies-flow` 由本版擬定；無外部 tracker。採 `standard`：只動原型 App 一個模組，`prospec/specs/features/` 尚無 Feature Spec 可被影響，性質是在既有 App 上改主流程與新增兩個畫面，不是跨層架構變更。
2. 實作底為 `design/survival-highlights` 分支（e479b2e，PR #8；route-experience fb10cc3 是其 ancestor），沿用其 view 狀態機（由 welcome、explore、guidance 三態改為 home、result、guide、card、map 五態）、導引頁、本機步行路線與「城市生存雷達」的四個亮點模組（`highlights.js`、`highlight-math.js`、`price-data.js`）；歡迎頁、「出發」鈕、四顆雷達入口與交通偏好不出現在首頁。這是 lead session 的建議，Ci 尚未明確拍板底分支（見 Open Questions）。
12. 四個生存亮點與三顆按鈕的對應：廁所 → 結果卡的「帶我去」可接水球倒數與本機步行路線；充電 → 結果卡為最近充電點，裝置電量低於 20%（或手動試玩）時自動疊上生存圈；網路 → 結果卡為最近免費 Wi-Fi，同心圓與密度留在「看地圖」。「房價含金量」與三急無關，不進主流程，去留見 Open Questions。既有亮點的所有估算標示（Wi-Fi 非訊號量測、倒數歸零非抵達、生存圈為直線上限、房價與貸款為假設）一律保留。
13. 主題沿用 survival 分支現行設計（淺色、紫 `#3525cd` 與橘 `#ff5e3a`），不為本 change 重新換膚；UI Scope 的「深色底亮綠」改為「沿用現行主題」。
3. `enable-friendly-routes` 的定位、bridge、導航退路、離線快取、資料併入、距離標籤規則全部沿用，本 change 不重寫、不放寬；兩個 change 同時開著，實作以本 change 的主流程為準。
4. 「最近」一律指直線距離最近；步行距離只在路網就緒時作為補充顯示，不改變挑選結果。路網資產約 20 MB，不阻擋首頁與結果卡的可用性。
5. 「充電」類別為名冊充電標記店家；「無障礙標記」取自既有四類服務標記中的 `accessible` 與公廁無障礙欄位，不新增資料集。
6. 開口卡被視為與撥號鍵同層級的面對面工具，不屬 D6 禁止的經平台互動；此為 lead session 判斷，待 Ci 或主辦確認。
7. 母語與輪椅偏好只存本機；App 不收集任何使用者資料。
8. 分鏡中的看護與長者是假設情境；若隊員有真實經驗可改用，但 demo 不得說成真實個案。
9. 翻譯句子不由 AI 自行產生定稿；印尼文、越南文、英文須找母語者或可信來源校對後才啟用。
10. demo 以 Android 實機為準；iOS WKWebView 的離線限制沿用 route-experience 交接文件的說明，不在本 change 處理。
11. 「3 秒內」是體感目標，以本機固定資料集量測；結果卡的「換下一家」上限 2 筆為暫定值。

## Edge Cases

- 該類別在全市資料中距離最近者超過 2 公里：仍顯示並明示距離，不隱藏；建議「看地圖」。
- 定位精度大於 100 m：結果卡仍出，沿用「精度不足」標示；距離旁加「約」。
- 同距離多筆：以資料順序穩定排序，避免每次重算跳動。
- 路網下載到一半斷網：導引畫面維持箭頭，不顯示半條路線。
- 母語設定為尚未校對的語言（例如舊版本殘留）：退回中文單面並提示。
- 開口卡開啟時螢幕旋轉或轉向店員：版面維持可讀，不重置回首頁。

## Functional Requirements

- FR-001：首頁三顆大按鈕、定位狀態列、看地圖與設定入口；無歡迎頁、無交通偏好（US-1、US-3）。
- FR-002：最近一家挑選（直線距離、類別篩選、輪椅偏好、無障礙資料不足標示）與結果卡內容、換下一家（US-1）。
- FR-003：帶我去：方向與距離導引加可選的本機步行路線，兩種距離分別標示；路網未就緒的退路（US-1）。
- FR-004：開口卡：類別固定句、四語言、內建文案、離線可用、未校對語言不上架、不記錄不送出（US-2）。
- FR-005：設定頁：母語、輪椅／推車偏好，只存本機（US-1、US-2）。
- FR-006：地圖頁降為第二層，既有功能完整保留，店家卡片加開口卡入口，返回路徑正確（US-3）。

## Success Criteria

- SC-001：固定位置與固定資料集下，三類別的結果卡那一筆皆等於程式外重算的直線最近者；換下一家依序正確。
- SC-002：輪椅偏好開啟時，有無障礙標記者存在的案例只回傳有標記者；不存在的案例回傳最近者並顯示「無障礙資料不足」。
- SC-003：無有效定位時按鈕不出結果卡，顯示需要定位與看地圖入口。
- SC-004：路網就緒與未就緒各一案例，導引畫面分別顯示「直線＋步行」與「只有直線」，標籤正確，未就緒案例無空白或載入卡死。
- SC-005：開口卡三類別四語言共 12 組句子與 README 校對紀錄一致；飛航模式下開啟無網路請求；語言清單不含未校對語言。
- SC-006：首頁、結果卡、導引、開口卡、地圖五個畫面在 390px 寬度可走完且無水平溢出；畫面搜尋無「出發」鈕與交通偏好。
- SC-007：`enable-friendly-routes` 的 SC-001 到 SC-007、SC-009、SC-010 在新結構下仍全部通過（回歸）。

## UI Scope

**Scope:** full
五個畫面：首頁（三顆全寬大按鈕、定位狀態列、看地圖與設定小入口）、結果卡（名稱、距離、方向、無障礙標記、三顆動作鈕、換下一家）、導引（大箭頭加距離文字，路網就緒時加路線）、開口卡（全螢幕雙面大字）、地圖（沿用現有）。主題沿用 survival 分支現行設計（淺色、紫橘主色），不重新換膚；大按鈕與開口卡字級以長者可讀為準；狀態不可只依顏色。雷達四模式的入口留在地圖頁工具列，不放首頁。

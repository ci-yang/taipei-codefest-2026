## 2026-11-08 ｜ D17 ｜ 介面加英日韓，機器翻譯初稿，雷達文案不翻

- **決定**：App 介面加英文、日文、韓文，繁中為基準。字串集中在 `i18n.js` 查表，任何語言缺 key 都退回繁中。沒選過時依 `navigator.language` 預設，選過存本機 `friendly.uiLang`。翻主流程：首頁、結果卡、帶我去導引、地圖面板、搜尋、詳細資訊、設定與提示訊息。城市雷達長文案（`highlights.js`，含導引中的步行距離卡）、資料集名稱、店家名與地址、`analysis.html`、`spec.html` 不翻。開口卡加日文、韓文句；未校對語言（en、id、vi、ja、ko）改成可選，開口卡下半與設定的語言選單標「機器翻譯」，`reviewed` 一律維持 `false`。介面切到英日韓時，開口卡母語預設跟著同語言。
- **理由**：Ci 2026-11-08 要求多語。比賽期間找不到母語者校對，所以先上機器翻譯初稿，並在畫面明示。範圍由 lead 指定為主流程全翻，長文案與資料名稱退回中文。
- **影響**：取代原本「未校對語言不得上 demo」的規則，`speak-card-strings.js` 註解與 README 已同步。導引畫面的步行距離卡仍是中文，在英日韓介面會和 HUD 混排；要翻需另改 `highlights.js`。新增介面字串時四種語言要一起加，`friendly-i18n.test.cjs` 會擋 key 不一致。母語者校對後，把開口卡的 `reviewed` 改 `true` 並填校對人與日期，介面字典則移除檔頭的機器翻譯註記。

## 2026-11-08 ｜ D16 ｜ 離線底圖改為多區域，新增北投學園路（demo 會場）一塊

- **決定**：App 的離線底圖從單一矩形改成多個區域。`data.js` 新增 `regions`，目前兩塊：「信義／大安東」`[[25.023,121.546],[25.044,121.574]]` 與「北投學園路」`[[25.121,121.454],[25.148,121.484]]`。`bounds` 保留為兩塊的外包矩形，只為向後相容。「是否有離線底圖」改成判斷是否落在任一區域內，兩塊之間仍算沒有底圖。新區域由 Overpass 一次 GET 取得（2026-11-08，OSM 基準 `2026-11-08T01:40:06Z`），用 `build-basemap-region.py` 重用 `build-friendly-data.py` 的 `load_osm` 轉換後併入，信義區原有 8,985 個 features 不變，新增 1,979 個。
- **理由**：Ci 今天在臺北城市科技大學體育館（北投區學園路 2 號）demo，原底圖只涵蓋信義一帶，到會場會顯示「此區尚無離線底圖」。步行路網已是全市，只缺底圖。原始信義 OSM 匯出不在 repo，所以採「保留舊 features、追加新區域」，不重抓信義。`data.js` 完整重建需要公廁與 Wi-Fi 的原始 CSV，本機沒有，所以新腳本只替換 `map`、`bounds`、`regions`，其他欄位原樣保留。
- **影響**：`data.js` 由 5,256,838 增為 5,859,166 bytes，仍遠低於單檔 25 MiB 上限。平台 API 用的 `data/friendly/map-data.geojson` 與 `manifest.json` 綁 `DATA_VERSION` 與 D1 快照，本次沒動，仍是信義單區。要再加區域，用同一支腳本帶新的 `--region` 與 OSM 檔即可；正式站部署與 APK 重打由 lead 安排。

## 2026-11-08 ｜ D13 ｜ 三急首頁視覺採「緊急停止鈕」，全 App 改用城市通官方色票

- **決定**：三急首頁的三顆大按鈕做成真實緊急停止鈕（e-stop）：直排三列，每列一顆蘑菇頭＋底座＋標示環，右側大字標籤（廁所／充電／網路）；按住時頂部沉進底座，放開後卡在按下位置並短震動，停約 180ms 讓人看見再進結果卡，回首頁時彈回。視覺原則沿用主工作樹 D12 的 prototype（`docs/prototypes/rescue-buttons-estop/`，在主工作樹、尚未進本分支）：低飽和、同色系柔和陰影，不做亮球高光與貼紙式裝飾。配色不再用 D12 v3 的自訂綠橘藍，全 App 改用 TownPass `tp_colors.dart` 官方 ramp（primary teal、secondary amber、grayscale、red、orange）；類別色為廁所 primary-500、充電 secondary-500、Wi-Fi primary-800、無障礙 grayscale-700；黃色標示環改為鋼環。字體 Roboto＋PingFang TC，字級只用 36／24／18／16／14／12，字重只用 400／600。同一輪一併定案：dark 主題的選中 chip 一律用深字；首頁「看地圖」一律進空狀態（不帶類別、不帶選取）；地圖上點 pin 只選取、不開詳細資訊；地圖面板刪掉 START 模式卡，城市雷達入口移到 footer。
- **理由**：Ci 要「有儀式感、不要太 AI、有按下去的急救感」，緊急停止鈕是大家都認得的實體物件，「按下卡住」讓人確定自己按到了哪一顆。服務跑在台北通 WebView 裡，用城市通官方色票、字體與字級，畫面才像宿主 App 的一部分，不像外掛頁。dark 主題 primary-600 與 grayscale-500 上的白字對比只有 3.79 與 3.66，不到 4.5，所以改深字。首頁「看地圖」若沿用上一趟結果卡的類別與選取，使用者會以為地圖只有那一類，空狀態才符合「第二層自己選」的規格。
- **影響**：主工作樹 D12「首頁以外頁面配色不跟著改」由本條取代，全 App 都走官方 ramp。官方 ramp 寫成 `docs/prototypes/friendly-route/app-ui.css` 的 `--tp-*` token。地圖圓點描邊改用類別的 text token，淺色底圖上的描邊對比要維持 3:1 以上。`navigator.vibrate` 在 TownPass WebView 的行為仍未實機驗證。

## 2026-11-08 ｜ 建立完整新北市福利版本

- **決定**：以獨立分支 `feat/new-taipei-benefits` 將福利雷達完整改為新北市版。主資料源改為新北市政府「福利補助資訊」每日更新 API，完整保留目前 152 筆；其中 28 項常用方案建立 115 年結構化深度規則。介面、資格欄位、官方連結與品牌一律使用新北市版本，移除福利頁的台北通帳號帶入，避免把臺北市民旗標誤當新北市戶籍。
- **理由**：文字改名無法處理兩市的所得財產門檻、租補金額、設籍期間、地方加碼與官方申請入口差異。新北官方開放資料已含資格、文件、申請方式及給付內容，能在不使用爬蟲的情況下建立可追溯候選目錄。
- **影響／重議**：152 筆候選不先用關鍵字刪除；只有官方文字明示全年受理、免申請或停辦時才自動標記受理狀態，其他保守標示待官方確認。28 項深度初篩與「可能錯過多少」估算要隨年度公告複核；未來若取得經授權的新北市個人資料橋接，才重新評估自動帶入，不能沿用台北通欄位假裝完成。

## 2026-11-08 ｜ 結果只顯示符合條件且仍可申請的方案

- **決定**：25 項深度比對只呈現「值得申請」與「待補資料」且未落在已知停收期間的方案，明確不符者不再顯示。165 項官方目錄候選須同時通過身分排除、相關度門檻與受理狀態檢查才會出現在畫面；同步時逐案讀取台北服務通案件明細 API 的 `acceptStatus`，不再把目錄的 `online=true` 當成正在受理。
- **理由**：把所有不符身分或已停止受理的服務列在結果中，會讓使用者誤以為那些項目仍可申請，也削弱真正可行項目的辨識度。
- **影響／重議**：送出後顯示「沒申請可能錯過多少」視窗，但只加總深度規則判定為可能符合、且能由官方金額可靠換算的項目；待補資料、泛用候選、依實支實付或個案核定而無法量化者均不灌入總額。線上暫停但案件頁仍列臨櫃辦理者，保留服務並明示「線上暫停、可臨櫃」；所有管道停收者隱藏。年度預算用罄等無法只靠 API 判斷的個案保留人工覆寫與官方公告依據。

## 2026-11-08 ｜ 官方服務候選先排除明確身分衝突

- **決定**：165 項官方目錄繼續作為可追溯來源，但畫面只顯示未被目前輸入明確排除的個人申請案件。未勾選原住民族、身障、役男家屬、孕產育兒、租屋、失業等必要情況時隱藏對應項目；申請人明確為雇主、事業、機構或團體的案件也不顯示。
- **理由**：原本只做關聯排序，即使身分明顯不符仍會列在「顯示全部」，容易被理解成可申請的結果。
- **影響／重議**：候選區會顯示本次排除數，但保留項目仍非資格核定。目錄缺乏可判定欄位時不得猜測排除；新增身分欄位或結構化規則後再縮小候選範圍。

## 2026-11-08 ｜ 官方服務候選必須揭露給付內容的可信度

- **決定**：能由已核對的深度方案或台北服務通目錄明確金額確認者，候選卡顯示「實際補助」；其餘項目只顯示「可能取得」的補助類型，並明確註記官方目錄未提供金額、比例或上限。
- **理由**：台北服務通目錄多數只提供申辦名稱與流程，不能把流程摘要當成補助內容；使用者也不應為了理解申請價值先讀一長段程序文字。
- **影響／重議**：同分排序時優先顯示已能說明給付內容的項目，原始目錄備註改為收合資訊。新增具體金額前必須能回溯官方來源，不能從名稱猜測。

## 2026-11-08 ｜ 資格結果必須同時回答「實際補助什麼」

- **決定**：25 項深度比對規則都保存並在結果卡醒目顯示「實際補助」，金額固定者顯示金額與週期，依級距或個案審查者則說明計算方式，不只列適用對象與資格門檻。
- **理由**：僅顯示所得、財產與身分條件，使用者仍無法判斷申請價值，並容易把相鄰的不同方案誤認為同一項。補助內容以 115 年主管機關頁面及現行法規人工核對，不從服務名稱猜測。
- **影響／重議**：年度或法規更新時，`benefitContent` 必須和門檻一起複核；金額若無單一答案則不得顯示臆測值。本次並依 115 年公告將都市原住民家庭租屋補貼所得門檻校正為每人每月 72,604 元。

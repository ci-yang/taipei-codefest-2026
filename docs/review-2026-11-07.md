## 發現（依嚴重度排序）

### 一、demo 會壞或看起來像壞了

**1. 實機上地圖最多空白 10 秒，定位慢一點就直接落到市政府**
- 位置：`apps/web/src/pages/MapPage.vue:64`（先 `await bridge.getLocation()`）→ `:73` 才 `new MapLibreMap`；逾時值在 `apps/web/src/composables/useTownPassBridge.ts:99`（`DEFAULT_TIMEOUT_MS = 10_000`）。
- 為什麼是問題：App 端 `GeoLocatorService.position()` 沒有逾時。它會先跳權限對話框，再呼叫 `Geolocator.getCurrentPosition()`，而且沒帶 `timeLimit`（`TownPass/lib/service/geo_locator_service.dart` 的 `position()` 結尾）。第一次開啟、在室內 GPS 冷啟動，或評審還在看權限對話框時，很容易超過 10 秒。結果是畫面停在「定位中…」最多 10 秒，地圖完全沒出來；逾時後顯示「無法定位」，以市政府為中心。App 晚到的回覆會被丟掉（`useTownPassBridge.ts:130`，佇列已經空了）。
- 實測：瀏覽器 mock 只等了 150ms，所以看不出來。這條是從程式碼推出來的，**還沒有在實機上量過**。
- 建議：先用市政府當中心把地圖建起來，定位回來後再 `map.flyTo` 並重新 `load()`。第一次定位的 timeout 拉到 20 秒左右。另外可以考慮把最後一次成功的位置存進 `sessionStorage`。

**2. 首頁關鍵字「水」太寬，會把明顯該去「避難」的句子導去「飲水機」**
- 位置：`apps/web/src/lib/features.ts:25`（`'水'`），比對順序在 `:36`。
- 實測（tsx 執行 `matchFeature`）：「颱風淹水要去哪避難」→ `water`，「水溝蓋壞了」→ `water`。
- 為什麼是問題：發表時評審很可能自己打字測試，這種錯一眼就看得出來。
- 建議：拿掉單字「水」，或改成「先算命中數，再看關鍵字長度」來取最佳結果，不要直接取第一個命中。

### 二、會誤導隊員

**3. HOW-TO 第 2 步指向不存在的 `geographyPoint` customType，照做會讓 `db:push` 失敗**
- 位置：`docs/HOW-TO-ADD-A-FEATURE.md:19`。在整個 repo 用 grep 搜 `geographyPoint`，只有這一行命中。
- 為什麼是問題：`apps/api/src/db/schema.ts:4-9` 明寫「不要宣告 geography，drizzle-kit 0.31 會加引號導致 push 失敗」，實際用的是內建的 `geometry(..., { type: 'point', mode: 'xy', srid: 4326 })`，再加一個 `(geom::geography)` 的 GiST 索引（`:25`）。隊員或 AI 照 HOW-TO 寫 customType，正好會踩到 schema.ts 註解警告的那個坑。
- 建議改成：「座標欄位照抄 `places.geom`：`geometry('geom', { type: 'point', mode: 'xy', srid: 4326 })`，再照 `places_geog_idx` 建 `(geom::geography)` 的 gist index」。

**4. CLAUDE.md 叫 AI 去讀 2025 版 bridge 參考，那份的用法是錯的**
- 位置：`CLAUDE.md:90`（「bridge 參考 `docs/reference/`（2025 版）」）；`docs/reference/WEBVIEW_BRIDGE_QUICK_REFERENCE.md:17-26`、`:55-66` 寫的是 `flutterObject.postMessage(...).then(...)` 和 `await flutterObject.postMessage(...)`。
- 為什麼是問題：官方 `postMessage` 不回傳 Promise，回覆是走 `message` 事件（見 A2）。照 2025 範例寫，`.then` 會丟 `TypeError`，`await` 則會拿到 `undefined`。檔頭雖然有一句「以 2026 官方為準」，但沒有說「這個呼叫模式本身是錯的」，AI 抄範例時不會發現。
- 建議：把 `CLAUDE.md:90`、`AGENTS.md` 同段改成「bridge 一律用 `apps/web/src/composables/useTownPassBridge.ts`，協定見 `docs/townpass-integration.md`；`docs/reference/` 是 2025 舊版，呼叫模式（`.then`）已失效」。在參考檔頭也補同一句。

**5. 隊員的 AI session 會被 prospec 卡住或帶偏**
- 位置：`CLAUDE.md:42-46`（CLI ≥2.4.0 是 required，缺了就「STOP… never substitute manual steps」）；`CLAUDE.md:106`；`.prospec/changes/000-skeleton-harness/metadata.yaml`（`status: story`）。
- 為什麼是問題：(a) README、RUNBOOK 都沒寫 prospec CLI 怎麼裝，這台機器上的是 `~/.local/bin/prospec`。其他 4 位隊員的 Claude 一開工就會照 L42 停下來。(b) 實跑 `prospec status`，它對每個 session 都回 `next: prospec-explore`，而且 000 的 premise 被 gate 擋住（`PREMISE_INCOMPLETE`）。照 L52「Station Transition Protocol」，AI 會被導去處理骨架 change，不會去做真正的功能。
- 建議：在 CLAUDE.md user 段加一句「沒有 prospec CLI 的人：跳過 prospec 相關步驟，直接照 HOW-TO 做」，並附上安裝方式（如果能公開取得的話）。000 改成 archive 或 abandon，或在 user 段明寫「000 只是範例，`prospec status` 指向它時忽略」。

**6. commit message 的語言規則互相矛盾**
- 位置：`CLAUDE.md:110`（`<type>(scope): 說明`）和 `:112`（「一律繁中」），對上 `CLAUDE.md:13` 與 `prospec/CONSTITUTION.md:10-16`（**[MUST]** git commit messages stay English）。
- 為什麼是問題：一邊暗示可以用中文說明，另一邊是 MUST。`prospec-verify` 會把中文 commit 判成 FAIL，不同隊員的 AI 也會各自選一邊。
- 建議：二選一寫清楚。黑客松建議直接把 Constitution 改成「commit 說明可用繁中」，因為這條是 prospec 產生的預設值，不是隊伍自己的決定。

**7. 「AI session 不自行 push」只寫在 TEAM-PROTOCOL，CLAUDE.md 沒寫**
- 位置：`docs/TEAM-PROTOCOL.md:47`，對上 `CLAUDE.md:95`（不可逆清單沒有 push）和 `:111`（「小改直推 main」）。
- 為什麼是問題：AI 一定會載入 CLAUDE.md，但不一定讀 TEAM-PROTOCOL。照 CLAUDE.md 讀，AI 可以自己直推 main。
- 建議：在 `CLAUDE.md:95` 或 `:111` 補「AI session 不自行 push／merge，交給地盤主人」。

**8. `.claude/settings.json` 免確認放行了會丟資料的指令**
- 位置：`.claude/settings.json` 放行了 `Bash(pnpm:*)`、`Bash(docker compose exec:*)`、`Bash(psql:*)`；`apps/api/package.json:12` 的 `db:push` 是 `drizzle-kit push --force`。
- 為什麼是問題：`--force` 會自動接受 data-loss 語句，例如改欄位名時它會 drop 舊欄位。再加上 `psql:*`、`docker compose exec:*`，AI 不必經過確認就能刪表、刪資料，和 CLAUDE.md:95「刪資料先問」衝突。
- 建議：從 allowlist 拿掉 `psql:*` 和 `docker compose exec:*`；或把 `db:push` 改成不帶 `--force`（drizzle-kit 會互動詢問，CI 再另外用 `--force`）。

**9. 地圖頁工具列會把所有非 about 的功能都當成「地點類別」列出來**
- 位置：`apps/web/src/pages/MapPage.vue:127`（`FEATURES.filter((x) => x.id !== 'about')`），以及 HOW-TO 第 5 步（`docs/HOW-TO-ADD-A-FEATURE.md:50`）。
- 為什麼是問題：照 HOW-TO 加一個 `bikes`（`to: { name: 'bikes' }`）之後，地圖頁的類別 chips 會多一顆「YouBike」。點下去會離開地圖頁，看起來像 bug。
- 建議：在 `Feature` 加一個 `kind: 'place' | 'page'`，MapPage 只列 `kind === 'place'`；或改成判斷 `PLACE_CATEGORIES.includes(f.id)`。

# iOS 模擬器端到端驗證：TownPass 殼 → 台北通微服務（2026-11-07）

結論：**整條路是通的。** TownPass（iOS 模擬器 debug）→ 釘選服務 → WebView 載入 Vite 首頁 → 點分類 chip → 地圖頁 → bridge `location` 回傳座標 → API `/api/v1/places` 回資料 → 地圖畫出點位，全部有截圖與 log 證據。
有一個 demo 風險：**第一次進地圖時，iOS 原生定位權限框還沒按，bridge 的 10 秒逾時就先到**，畫面會退回「無法定位，改以臺北市政府為中心」。詳見〈發現〉第 1 點。

## 發現（依 demo 影響排序）

1. **首次定位權限框 vs 10 秒逾時（demo 風險，高）**：第一次進地圖時 iOS 跳原生權限框，使用者如果 10 秒內沒按，bridge 逾時，畫面固定在「無法定位，改以臺北市政府為中心」；按了允許後**這一頁不會自動重抓定位**，要離開地圖再回來才會變「已用台北通定位」。
   - 推測（未驗證）：10 秒內按「允許」應該就能拿到位置，因為按完之後再進一次地圖立刻成功。
   - Demo 建議：上台前先在該手機進一次地圖、把定位權限允許掉；或在 App 層級先要權限。要不要改程式由 Ci 決定，本次未改。
2. **模擬器定位**：開 App 前用 `xcrun simctl location set` 設的台北座標沒有生效（第一次回的是舊金山預設值），App 啟動並取得權限後再設一次才生效。只影響模擬器 demo；實機不受影響。
3. **命名不一致（低）**：服務格標題是「台北通通通懂台北」，但 WebView app bar 標題是「台北通微服務」。服務格標題在 4 欄寬度下折成兩行，左側貼齊螢幕邊緣。
4. **文件與程式碼的 dart-define 名稱不一致（中，會讓照文件 build 的人白跑）**：程式碼讀 `CODEFEST_SERVICE_URL`（`TownPass/lib/config/codefest.dart:12-13`），但 `docs/` 裡有 6 處寫 `OUR_SERVICE_URL`（例如 `docs/townpass-integration.md` §5 的 build 指令）。照文件傳 `OUR_SERVICE_URL` 會被忽略、落回預設網址。
5. 第一次啟動先跳「通知」權限框，擋在首頁前面；demo 冷啟動要預期多按一下。

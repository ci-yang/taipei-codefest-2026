TAIPEI CODEFEST 2026 · 拿不到 / 資源限制

友善同行
沿途找得到，離線帶得走。

趁還有網路，先找好沿途可詢問的 Wi-Fi、充電與友善服務，把地圖與店家資訊一起帶走。

這版把 Ci 討論的五項功能做成可操作原型。真正的差異是出發前安排資源、途中保留資訊、到店前看懂不確定性。官網已經有地圖與友善項目篩選；本提案延伸行程、離線與回報流程。既有友善店家地圖

先玩這 3 步，約 3 分鐘

01 找沿途資源載入示範路線，切換 Wi-Fi／充電，調整搜尋距離，打開一間店。
02 斷網也能看完成離線下載，再切換離線示範。查看地圖、店家電話及可出示的詢問卡。
03 試回報與互助試填本機評論，回到連線模式開啟附近協助，切換接收者查看分享範圍。

地圖使用真實店家與 OSM 道路；路線目前是直線示意，不能當作步行或無障礙導航。

題目貼合在哪裡

主要對象：已有手機，但行動網路、電量或現場協助受限的市民，以及協助安排行程的人。經濟弱勢的受益前提，是清楚知道使用服務是否要消費；目前資料沒有這個答案，必須顯示待確認。

對應方向：找公共或店家網路資源、提前下載以降低連線依賴，並用大字詢問卡與可列印資訊協助到店詢問。無障礙與廁所是同行需求。這版沒有宣稱解決無手機、偏鄉網路覆蓋或長者所有使用障礙。

「拿不到」的核心驗證：一個人斷網後，能否仍讀到之前存好的地圖、店家位置與詢問方式？實際改善多少，需與目標族群測試，現在沒有成效數字。

五項功能，清楚分開可用與示範

功能這版可操作正式服務下一步
四類資源地圖
P0		充電、無障礙、廁所、Wi-Fi；任一符合的多選篩選與店家清單。持續更新官方名冊；補上可追溯的消費條件。
多目的地路線
P0		用範圍內真實店家作起點／目的地，依順序連線並找沿線候選點。接入可用的開源路網路由；地址解析與真實步行可達性驗證。
品質與評論
正式 P1		本機試填；用「尚無回報／有順利回報／需再確認」呈現數量、日期與原因。公開回報後端、身分與重複回報處理、檢舉和維護責任。
資源範圍與離線
P0		沿線距離篩選；保存本地向量底圖、店家資料與路線，顯示時間與範圍。在比賽 Android／TownPass WebView 實機驗證保存容量與重開行為。
附近協助
正式 P1		本機雙角色示範；預覽、位置同意、選擇是否分享路線、回應、撤銷與到期。多人同步、真正接收確認與通知；參與身分、到期規則與值守責任。

P0／P1 是正式產品的開發順序。五項功能都在本次 prototype 的展示範圍。

資料是真的，未知也保留

  1. 店家：臺北市友善店家清冊繁中 CSV，更新 2026-07-20；原始 993 筆、臺北市地址 986 筆。原型截取信義／大安東側框選範圍的 103 筆，沒有捏造店家。
  2. 標籤：1 代表名冊標示；空白是未標示。名冊沒有即時品質、插座空位、免消費規則或結構化營業時間。官方友善項目說明不能推導所有人都可免消費使用。
  3. 底圖：© OpenStreetMap contributors，採官方開放資料 API 擷取的地方向量快照，依 ODbL提供；下載本次底圖資料。不使用 Google Maps／Mapbox 或預抓 OSM 圖磚。
  4. 回報與協助：不預填虛構評價；使用者操作只在這個瀏覽器示範，沒有通知真人。星等、救援抵達或已驗證品質均不宣稱。

值得先做；多人協助留出實作邊界

可行性判斷：名冊已有地點與四種服務，篩選、沿線距離與固定區域離線包都能用開源元件完成。最需要額外工程與營運的，是公開評論及多人互助。這份原型用可操作流程確認需求，不把它們寫成已上線的正式服務。

評審問：和現有友善店家網站有何不同？

「既有網站能查店家。我們讓使用者把需要的店家放進多站行程，在還有網路時完成保存；途中斷網仍能看底圖與詢問方式。品質回報用來揭露資訊依據與未知條件。」

評審問：圈內一定有 Wi-Fi 或一定能獲救？

「圈是幾何搜尋範圍，只用來找到附近候選店家。它不是訊號覆蓋、可步行距離或救援保證；實際使用條件仍須向店家確認。」

評審問：這是救援 App 嗎？

「此處是非緊急資源互助的本機流程示範。正式多人協助需另外完成接收確認、撤銷到期與通知服務，本版不會向真人發送求救。」

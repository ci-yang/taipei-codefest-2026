# 友善路線：需求與資料核對紀錄

核對日期：2026-11-07。此檔保存本版規格的來源，不宣稱已完成使用者研究。

## 需求來源

Ci 在本輪對話提出友善店家主題，附手繪介面與官方網址，要求分析後製作 prototype、發布報告台，以及先用 `prospec-new-story` 寫第一版規格。需求摘要如下；這是需求轉述，不是虛構訪談或測試結果。

1. 地圖可篩選行動裝置充電、無障礙友善、友善廁所與 Free WiFi。
2. 可輸入起點及複數目的地，在路徑上視覺化店家與服務類別。
3. 店家品質有視覺等級，開放評論。
4. 路徑顯示可提供資源的店家範圍，沒有 WiFi 時切換快取地圖。
5. 在線時可向其他使用者求助，其他人看到求助地點及路徑。

原始參考：[友善店家地圖](https://friendlystore.taipei/map/tw/pg1/3/qop/41)。使用者說明的競賽分組為「拿不到」，對象包括經濟弱勢、偏鄉居民與獨居長者；本提案優先連結公共網路，不宣稱同時涵蓋全部對象。Prototype 另提出可出示或列印的大字詢問卡，作為協助者交接與現場詢問的設計方向；這不代表已建立實體窗口或店家合作。

## 尚未驗證

- 沒有目標族群訪談、可用率、改善幅度或需求頻率數據。
- 沒有店家合作、免消費承諾、即時容量或現場 WiFi 訊號測試。
- 「台北通裡沒有」是 Ci 的觀察，尚未完成 App 全功能盤點。
- 需求中的「沒 WiFi」在本版改用「連線不可用」呈現；瀏覽器的網路提示不保證可辨別 WiFi，也不等於伺服器已接收求助。
- Prototype 的路線與互助屬示範；真實路網、共享評論與跨裝置互助仍須後續實作及驗收。

## CLI 環境紀錄

Prospec 版本 2.6.0。隔離 worktree 執行 `prospec status` 與新建 Story 時，對歷史 `000-skeleton-harness` 回報 conflicting history；`diff -ru` 比較其與主工作目錄的歷史資料夾為相同內容，`history import --dry-run` 仍拒絕。

因此本次由主工作目錄執行 CLI 新建與後續 metadata 操作，再精確搬入本次交付 worktree；不改寫歷史 bundle、不手寫 metadata、不切分支或操作其他人的內容。

友善同行：沿途找得到、離線帶得走的友善資源

第二版規格｜手機 App 流程：地圖首頁 → 行程設定 → 路線確認 → 開始行程。原有五功能與本輪 GPS／日期／歷史／路線比較皆須展示；P0／P1 僅區分後續正式服務順序。

這版怎麼走

  1. 01 地圖首頁取得目前位置，按「開始」。
  2. 02 設定行程選日期、歷史、起點與多個目的地。
  3. 03 確認路線比較最短路徑與資源最多，再選擇。
  4. 04 開始行程查看沿途資源、保存離線與詢問互助。

以下每個故事可展開看驗收條件。GPS 不可偽造；歷史不預填；路線必須算出來。

為什麼做

Ci 提供的五項需求，將友善店家從分類查詢延伸為「外出途中取得資源」的入口；主要服務缺乏穩定網路、電力或現場協助的市民與協助者，對應競賽「拿不到」。官方開放名冊有店家位置及服務標籤，但沒有服務品質回報、即時可用狀態與免消費條件；現有官網已能依友善項目篩選並提供單店路線入口。Ci 本輪進一步要求 GPS 起點、日期與歷史、路線比較及手機 App 分頁；能否改善目標族群取得資源的結果，仍是待實測的產品假設。

七個使用者故事

US-1: 找到所需服務 [P0]

作為缺少穩定網路或電力的市民，我想按需求找店家，以便找到可詢問的資源。

驗收情境：

  • WHEN 我選擇充電、無障礙友善、友善廁所或 Free WiFi 的一項或多項，THEN 地圖與清單同步呈現符合已標示項目的店家，並明示多選為「任一符合」。
  • WHEN 我查看店家，THEN 顯示名稱、地址、服務標記、來源與資料日期；空白標記顯示「未標示」，未確認條件顯示「待確認」，不宣稱免費免消費或目前可用。
  • WHEN 篩選沒有結果，THEN 顯示零筆與清除篩選入口，保留我的路線。

獨立測試： 不建立路線也能單獨切換四類篩選，逐筆對照固定資料集的服務標記。

US-2: 比較多站行程的建議路線 [P0]

作為安排外出的市民或協助者，我想比較較短與資源較多的路線，再選擇適合這次行程的方案。

驗收情境：

  • WHEN 我設定有效起點與依序經過的 1–5 個目的地並按下一步，THEN 進入獨立確認頁，顯示可用路線、各站順序、距離、符合需求的沿線店家數與類別。
  • WHEN 系統提出「最短路徑」及「資源最多」方案，THEN 最短明示限定本次可用路網；資源最多明示限定本次產生的候選，按相同需求與距離範圍計算不重複店家數，並呈現兩者的距離與資源差異。
  • WHEN 我選擇方案並按「開始行程」，THEN 進入該方案的行程地圖；返回修改日期、起迄或需求後必須重新確認，不沿用已失效的比較結果。
  • WHEN 地點需要接至可用路網，THEN 只允許每段不超過 120 m 的端點接線，另列接線距離並納入總距離，標示接線未驗證現場通行；超限即拒絕該地點並提供修改入口。
  • WHEN 地點無法辨識、超出路網、路段不連通或沒有不同的替代方案，THEN 說明原因與可修改項目，不以直線跨越不連通路段、不捏造第二條路線；原型路線不保證現場通行或無障礙。

獨立測試： 固定起點及三目的地，逐一測試站序、增刪、方案切換與開始；以相同候選資料核對距離／去重店數，並測試單一路線、不連通、端點接線限內與超限情況；接線長度須可重算且包含在總距離。

US-3: 看懂品質依據並留下回報 [P1]

作為實際使用友善服務的市民，我想回報指定服務的經驗，讓下一位出發前多一項判斷依據。

驗收情境：

  • WHEN 店家尚無回報，THEN 顯示「尚無回報」；有順利回報且無問題回報則標「有順利回報」；存在條件有限或未能使用的回報則標「需再確認」，各級皆有文字與圖示。
  • WHEN 我提交服務類別、使用結果及文字回報，THEN 顯示其日期與來源，更新該服務的數量和等級；保留各結果數量，不以總分掩蓋問題。
  • WHEN 回報只存在本機或尚未查證，THEN 明示其狀態，不顯示為其他人評論或官方認證，並提供刪除自己回報與檢舉入口。

獨立測試： 以隔離測試資料依序加入順利、條件有限回報，再刪除，核對三種等級及數量，不建立真實消費紀錄。

US-4: 看見資源範圍並離線帶走 [P0]

作為可能途中斷網的市民，我想先保存路線與店家資訊，以便離線仍知道可前往詢問的地方。

驗收情境：

  • WHEN 我調整沿途範圍，THEN 顯示距路徑指定直線距離內的候選點；圖例明示這是資源搜尋範圍，不是 WiFi 訊號、可步行範圍或救援保證。
  • WHEN 我要求下載離線包，THEN 先明示會保存本次起點與路線；涵蓋範圍的底圖、路線、店家資料與重開頁面所需內容全部保存成功才顯示完成，任何一項失敗都不顯示「已快取」。
  • WHEN 我完成儲存後斷網並重開頁面，THEN 自動顯示已存底圖、路線與店家資料，列出儲存時間及涵蓋範圍，並保留服務不保證現場可用的提示。
  • WHEN 沒有已存內容、僅部分保存成功或要求範圍外的新路線，THEN 說明缺少離線資料，不假裝新路線已完成；保留仍可讀的內容。

獨立測試： 保存固定路線後關閉網路並重開頁面，逐一核對底圖、路線、店家與時間；模擬底圖或頁面內容保存失敗，確認不報完成；清除保存內容後重測無離線資料狀態。

US-5: 明確同意後向其他人求助 [P1]

作為需要充電或連網協助的外出市民，我想在線上發布短時互助請求，讓願意協助的人看到我選定的地點與路段。

驗收情境：

  • WHEN 我選好需求與求助點準備發布，THEN 先預覽將公開的資料，再要求我明確同意；路線分享預設關閉，未勾選時不包含路線，勾選時須另外確認欲公開路段；只有服務確認接收後才顯示「已發布」，不自動分享住家、完整行程或持續定位。
  • WHEN 另一位市民查看有效請求，THEN 只看到已同意的需求、地點、路段與到期時間，可回覆願意協助；回覆不等於協助者已到達或資源保證可取得。
  • WHEN 我取消、結束或請求到期，THEN 其他市民不再看到有效求助點；斷網取消顯示「取消待確認」，不假稱已撤回。
  • WHEN 發布時斷網或連線失敗，THEN 請求留為未送出的草稿，不顯示已送達；重新連線後仍需再次確認才送出；僅偵測到網路不宣稱一定使用 WiFi。

獨立測試： 以兩個測試角色完成草稿、預覽、同意、發布、回覆、取消／到期；先斷言未勾路線時接收者看不到路線，再勾選並確認路段後核對只見該路段；故意斷網後核對未送出及取消待確認狀態。

US-6: 從目前位置開始手機行程 [P0]

作為拿著手機外出的市民，我想先看地圖，再用目前位置開始設定行程，避免一次讀完全部功能。

驗收情境：

  • WHEN 我開啟首頁並允許定位，THEN 地圖標示裝置回傳的目前位置、定位精度與取得時間，行程設定的起點預設使用此位置，不將展示座標標成 GPS。
  • WHEN 我在首頁按「開始」，THEN 進入行程設定頁，再依序進入路線確認及行程地圖；每頁有明確主要操作及返回入口，不同頁的全部表單不堆在同一畫面。
  • WHEN 定位被拒、逾時、不支援或精度不足，THEN 顯示相應狀態、重新定位及手動選起點入口；沒有有效位置時不顯示定位成功。
  • WHEN 真實位置在示範資料或可用路網範圍外，THEN 保留真實位置與範圍提示，停止以該起點建立建議路線；只有我主動選擇示範起點才切換，且持續標明示範。

獨立測試： 分別注入已知位置、拒絕、逾時、低精度與範圍外結果；核對顯示值及起點來源，再於 390px 寬度走完四頁且無水平溢出。

US-7: 選日期與重用自己的歷史路線 [P0]

作為經常外出的市民，我想選擇出發日期並套用自己保存的行程，減少重複輸入。

驗收情境：

  • WHEN 我進入行程設定頁，THEN 可選日期、歷史路線、起點及目的地；新行程預設裝置當日日期與可用的目前位置，畫面不依選定日期宣稱店家正在營業。
  • WHEN 我確認路線並明確選擇保存為歷史，THEN 才將日期、起迄點及選定方案存入本機歷史；初始歷史為空，保存失敗不得顯示成功。只下載已提示保存內容的離線包時，可保存其必要起點與路線，但不自動新增歷史。
  • WHEN 我套用或刪除歷史行程，THEN 套用會還原站序與方案偏好、保留這次已選日期並重新計算，舊起點標為歷史起點；刪除後該筆不再出現，不把歷史紀錄當作目前位置或即時路況。

獨立測試： 從空白儲存區確認路線；未保存時重開仍無歷史或 GPS 快照，保存歷史後可套用與刪除；只下載離線包時可恢復起點但歷史仍空，日期與起點來源須符合上述規則。

本版假設

  • 名稱 enable-friendly-routes 與產品暫名「友善同行」由本版擬定；無外部 tracker。採 full，因跨地圖／路線、品質、離線與互助需求；不是既有功能的小修。
  • 核心對象先收斂到已有手機、網路或電力受限的市民與其協助者；無障礙與廁所為同行需求，不宣稱同時解決無設備與偏鄉覆蓋。
  • 原有五功能與本輪 GPS、日期、歷史、路線比較、App 分頁均為 prototype 必交；P0／P1 只區分正式服務順序。公開評論與真人互助尚未上線。
  • 多選預設任一符合；1–5 個目的地按輸入順序，不自行重排。最短只比較固定站序的本地可用路網；資源最多只比較本次候選，用相同範圍與四類篩選計算去重店數，不宣稱全市全域最優。端點接線上限採本版 120 m，須另列距離與未驗證通行提示。
  • 品質等級採 US-3 的可解釋規則，不套用官方認證；首版不因沒有回報而隱藏店家。回報的時效與是否本人使用尚未驗證，畫面應保留日期。
  • 官方服務標記只代表名冊登錄；免消費、營業時間、插座空位及訊號狀態都不由標記推定，須由店家或後續可追溯核對補足。
  • Prototype 使用本地道路快照產生路線比較，但未完成現場通行與無障礙驗證，不作正式導航保證。評論為本機試填，互助為雙角色示範，不通知真人，不產生虛構評論或到場紀錄。
  • 正式互助只處理非緊急資源協助，需可辨識發布者與撤回權限；預設僅分享明確同意的求助點，路線預設不勾選，須額外確認哪些路段可公開；短時到期且不持續追蹤。到期時長待計畫站確定；沒有使用者實測成效。
  • App 版採使用者參考圖的深色、亮綠與簡約卡片，手機優先、桌面為手機預覽容器；仍是可開啟的 Web prototype，不宣稱已交付原生 APK。每次請求為一次定位，是否持續追蹤不在本版範圍。
  • 日期預設裝置當日；歷史只在明確保存為歷史後建立於本機，無預填假紀錄。GPS 僅供當次設定，除非使用者選擇保存歷史，或下載已明示包含起點的離線包，才持久保存；不傳給外部路由服務。公開互助另需同意；精度門檻與示範路網範圍須在畫面明示。

邊界與失敗處理

  • 座標缺漏或超出資料涵蓋範圍：名冊可查，但不能任意補點；先提示無法顯示在地圖。
  • 位置回傳太舊、低精度或定位期間起點已被手動修改：提示重新定位，不用較晚回呼覆蓋手動起點；同名地點以地址辨識。
  • 同店同時有相反回報：顯示各結果數量與日期並標需再確認；疑似濫用回報可檢舉，不立即改官方欄位。
  • 店家名冊、路網或快取版本改變：歷史套用須重新比較；離線僅讀已保存路線，不建立範圍外新建議，不把舊資料改標即時。
  • 互助到期、取消與回覆同時發生：已終止狀態不恢復有效；不得以畫面切換製造真實送達／已到場紀錄。

功能需求

  • FR-001：四類需求篩選、同步地圖與清單、未知值及來源日期（US-1）。
  • FR-002：多目的地固定站序、獨立路線確認頁、最短／資源最多的計算範圍與差異、方案選取及開始行程（US-2）。
  • FR-003：分服務品質回報、數量／日期／分級依據、刪除與檢舉、模擬與真實隔離（US-3）。
  • FR-004：資源搜尋範圍可視化，與 WiFi 訊號及步行可達性分開說明（US-4）。
  • FR-005：底圖、路線、店家及必要頁面內容全部保存成功的離線包、時間／範圍、斷網重開與無快取狀態（US-4）。
  • FR-006：互助需求、位置與路段同意、有效狀態、接收確認、回覆、撤回／到期及未送出處理（US-5）。
  • FR-007：手機四頁流程、真 GPS 與起點預設、精度／時間、拒絕與範圍外回退，手動及示範起點的來源區分（US-6）。
  • FR-008：日期選擇、本機歷史的明確保存／套用／刪除，以及定位資料保存界線（US-7）。

驗收標準

  • SC-001：固定資料集四類篩選結果與來源旗標逐筆一致；零筆與未知值各有一項通過案例。
  • SC-002：起點＋三目的地可增刪與比較；總距離含端點接線、去重店數可由固定資料重算；接線限內／超限、同一路線與不連通各有一項案例。
  • SC-003：三種品質等級皆可由有日期、分類的測試回報重現；無回報店家不出現假評分。
  • SC-004：保存後斷網重開可讀同一底圖、路線、店家與儲存時間；任一必要內容保存失敗不報完成，未保存及超出範圍各有明確狀態。
  • SC-005：兩個測試角色可重現預覽／同意／發布／回覆／取消／到期；不勾路線時接收者看不到路線；斷網時零筆請求被誤標送達。
  • SC-006：畫面和交付文件列出資料來源；全部模擬互動都有標記；不得把以上測試成功率寫成使用者成效。
  • SC-007：GPS 成功、拒絕、逾時、不支援、低精度與範圍外各有一項案例；零筆示範座標被標成真 GPS。
  • SC-008：空白歷史、未保存、保存成功／失敗、套用與刪除均有案例；未選任何保存的 GPS 不持久留下，只下載離線包不得自動建立歷史。
